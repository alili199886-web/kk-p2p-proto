赛事大厅 · 开盘坐庄需求标注

本期在 IM 既有赛事与盘口范围内，升级为「私盘模式按赛事开盘坐庄」。原比赛与既有投注项卖出完全不受影响。

商户开关

  • 开关层级：后台 P2P 全局开关（p2p_enabled）是前置条件，优先级最高；其下的商户 P2P 开关与商户私盘开关平级、各自独立——商户 P2P 开关只控制投注项卖出，不影响私盘。
    · 投注项卖出可用 = 全局开关开启 且 商户 P2P 开关开启
    · 私盘可用 = 全局开关开启 且 商户私盘开关开启
    全局开关关闭时，P2P 与私盘的前端入口全部隐藏；两个商户开关各自关闭时，只隐藏自己那一块。
  • 关闭后的隐藏范围：
    · 赛事页：赛事行「开盘」按钮、赛事列表的私盘行、筛选行的「私盘」胶囊；
    · 我的卖出页：私盘页签隐藏，列表只保留「投注项卖单」单页签形态；本人仍有未结算的盘时按下一条例外处理；
    · 购物车：私盘投注项的相关展示与入口；
    · P2P 开关关闭时，另含「P2P」胶囊、赔率格红点与比赛行的 P2P 入口。
  • 软关闭，存量盘继续执行：关闭前已存在且未结算的私盘继续执行至赛事结算，已成交子单正常结算、未消费押金结算后退回。
  • 存量盘的管理入口保留：本人仍有未结算的盘时，「我的卖出」的私盘页签保留可见，可进入开盘详情查看；但不可新开盘、不可新增盘口、不可补充额度，底部仅保留「停止收单」，并提示「商户已关闭私盘，本盘不可新增盘口与补充额度，可停止收单或等待赛事结算」。本人全部盘结算完成后，私盘页签随之隐藏。

开盘入口

  • 入口位于 P2P 已生效联赛下，每场比赛行时间/场次信息旁的「开盘」按钮，不与赔率列重叠。
  • 开盘范围 = IM 在售且未开赛的赛事，含今日盘与早盘；滚球（已开赛）不展示开盘入口，切换到滚球页签时该页全部赛事均无开盘入口。
  • 互斥仅限同一会员：同一会员对同一场比赛，开盘坐庄与投注项卖出二选一——本人已有进行中的私盘时该场「卖出」入口置灰，本人已有该场投注项卖出时「开盘」入口置灰。不同会员互不影响：该场官方盘已有其他会员的 P2P 挂单时，仍可正常开盘；私盘档位只在私盘内成交、官方盘卖单簿只含投注项卖出档位，两者押金池、撮合与结算彼此独立，新开私盘不影响官方盘上已有 P2P 挂单的购买。
  • 提交时二次校验：开盘弹窗打开后至点击「确认开盘」期间，若本人在该场挂出了投注项卖出，提交时拦截并提示「你对该场已有投注项卖出，不可再开盘」，弹窗关闭。
  • 赛事所属联赛需在可坐庄联赛白名单内，不在名单内不展示入口。
  • 庄家坐庄权限被运营关闭时不展示入口，存量盘不受影响。

私盘展示规则

  • 开盘 = 复制该比赛生成私盘，名称 = 原比赛名 + 庄家昵称（开盘弹窗设置，最长 12 字符，默认取上次值）。
  • 私盘紧随原比赛下方展示，右侧「私盘」标识（样式同 P2P 标识，替代其位置）。
  • 仅展示庄家开放的盘口：开放项显示庄单赔率（独赢为欧洲盘 = 港盘 + 1，让球/大小为港盘），未开放项显示 -- 置灰，单项封盘显示锁定态。
  • 可见性：盘为卖出中时展示；整盘售罄 / 已关闭 / 已结算后私盘从列表消失。
  • 多位庄家可各自对同一场比赛开盘，各生成独立私盘，按开盘时间排列；同一庄家同一比赛限 1 个进行中的盘。
  • 开盘与投注项卖出互斥：同一会员对同一场比赛，开盘坐庄与投注项卖出二选一。已有进行中的盘时，该场全部投注项的「卖出」入口置灰并提示「该场已开盘，不可再单独卖出」；已有该场进行中的投注项卖出时，该场「开盘」入口置灰并提示「该场已有投注项卖出，不可再开盘」。两者的「进行中」判定一致：卖出中、已封盘计入，已售罄 / 已关闭 / 已结算不计入。
  • 「进行中」的判定范围：卖出中、已封盘计入（私盘仍在列表或可恢复）；已售罄、已关闭、已结算不计入，庄家可对同一比赛再开新盘——售罄盘已从列表消失，不会造成重复占位。
  • 单场私盘展示上限 N 个（默认 5），超出折叠为「查看全部私盘」，折叠不影响卖单簿成交。
  • 筛选行「私盘」胶囊：开启后仅展示私盘。
  • 比赛卡片的队伍信息：每行为「球队图标 + 队名 + 红黄牌角标」，行右侧展示该队当前比分；黄牌为橙底白字方块、红牌为红底白字方块，牌数为 0 时该角标不展示。队名下方一行展示「直播图标 + 半场比分 + 角球图标与角球比分」，对应字段缺失时该项不展示、整行无内容时不占位。官方盘与私盘的这部分展示规则一致。
  • 私盘行版式与官方盘一致：标题行为私盘名称 + 右侧「私盘」标识；开赛时间展示在队名上方；盘口名称列头（全场 / 上半场 的 独赢、让球、大/小）与官方盘同位置同样式；「全部 N▸」入口展示在队名下方（与官方盘的「所有盘口 N▸」同位置）；底部翻页指示点与左右滑动切换全场 / 上半场的交互也与官方盘一致，与该场官方盘共用同一分页状态（官方盘切到上半场时，其下的私盘同步切换）。
  • 私盘的「全部 N▸」入口：赛事列表的私盘行只展示六类主玩法（全场 / 上半场 的 独赢、让球、大/小）。当私盘开了这六类之外的盘口（如进球、波胆、特殊玩法）时，展示「全部 N▸」（N = 该私盘开放的盘口总数）；点击进入盘口详情页，页面仅展示该私盘开放的盘口、按该私盘的庄单赔率显示，点击任一盘口即加入购物车并按私盘规则投注。私盘开放的盘口全部落在六类主玩法内时不展示该入口。

购物车（投注面板）

  • 形态：底部固定面板（约占屏高 58%），不使用弹窗、不对赛事列表加蒙层；面板打开时赛事列表仍可滚动、赔率格仍可点击，选中新投注项实时加入购物车。
  • 顶部：买入 / 卖出两个页签等分居中；右上角常驻关闭按钮（×），点击仅收起面板，已选投注项保留，可再次点击赔率格或购物车入口重新打开。不展示注单计数与清空图标。
  • 选中私盘投注项时隐藏「卖出」页签：私盘只承载开盘庄家本人的档位，其他会员不能往该私盘挂单，因此私盘投注项不支持卖出；若已停留在卖出页再选中私盘项，自动切回买入页；强行调用卖出页提示「私盘投注项不支持卖出」。关闭按钮在此场景仍保留。
  • 投注卡片：标题为「盘口 + 队名」（如 +0.5/1 瓦特福）；第二行「玩法 · [盘口类型]」；第三行「主队 VS 客队」；第四行「足球 · 联赛」。右上角为赔率与删除图标。
  • 档位表：该投注项存在不低于官方赔率的 P2P 档位时展示（档位 / 卖出赔率 / 可购额度 / 购买计划四列）；无此类档位时整块隐藏，输入框下方直接接数字键盘，按官方赔率投注。
  • 底部：自动接受任何赔率开关与说明入口、余额；按钮行为「串关 / 单关」与「投注 CNY 合计」（附最高可赢），不设「返回」按钮，收起面板走右上角关闭按钮。
  • 投注成功后：已投注的投注项自动取消选中、金额清空，购物车收起并回到赛事列表，再弹出注单确认；若仍有未投注的选中项，点「保留注单，继续投注」会重新打开购物车。

串关限制

  • 私盘投注项不参与串关：私盘项仍在串关页展示，置灰并标注「私盘投注项不支持串关，仅官方盘投注项可参与」，不计入组合、不计入串关资格判定。
  • 同场不可互串：同一场比赛的多个投注项不允许串关，包括「一个官方盘 + 一个私盘」这种组合（私盘复制自原比赛，视为同一场）。串关组合按原比赛去重，每场只取先选中的一项参与，其余置灰并标注「与已选投注项属同一场比赛，同场不可互串」。
  • 串关按钮激活条件：可参与串关的投注项需来自 ≥2 场不同比赛。购物车内只有同一场赛事时（无论官方盘或私盘），串关按钮置灰；已进入串关页但可串项不足 2 场时不生成组合行，提示「可串关的投注项不足 2 场，无法生成串关组合」。

开盘门槛（确认时逐条校验，任一不满足即拦截）

  • 开放盘口数 ≥ 3（min_items）
  • 盘押金 ≥ 1,000（min_deposit，整盘一笔，全部盘口共享）
  • 开赛前 10 分钟内禁止新开盘（freeze_minutes）
  • 门槛的前置与临界：IM 交集内可开盘口不足 min_items 时不展示开盘入口；账户余额需 ≥ 盘押金，等于时允许；封盘前置时间以服务端接收开盘请求的时间为准，不以客户端点击时间为准。

赔率格与卖单簿

  • 原比赛有庄家档位的盘口展示红点，变化实时刷新；私盘赔率格样式与官方盘一致，不做颜色区分。
  • 卖单簿按来源隔离：私盘的卖单簿只有「该开盘庄家的档位 + 官方无限档位」；官方盘的卖单簿只有「投注项卖出档位 + 官方无限档位」。三类档位不会同时出现在同一个卖单簿中。各自内部按赔率降序 → 同赔率卖出时间优先 → 官方固定最后。
  • 「私盘」与「P2P」标识互斥：私盘表示私人开盘，仅标注在私盘行；P2P 表示有会员对该场玩法项坐庄，仅标注在官方盘（原比赛与联赛头）。官方盘不展示私盘标识，两者不同时出现在同一对象上。
  • 展示范围：赔率低于官方赔率的档位不展示（视为已下架，不可成交）；赔率不低于官方的档位全部展示，不做数量截断。
  • 可见高度：卖家档位最多可见 5 档，超过 5 档时区域内出现滚动条，滚动查看其余档位；官方档位固定在最后一行，不参与滚动。

我的卖出 · 需求标注

私盘与既有投注项卖出并存，分页签展示，筛选对两个页签同时生效。

结构

  • 顶部为两个页签（样式同买单列表）：投注项卖单（默认选中，展示官方盘的投注项坐庄数据）与私盘（展示开盘坐庄的盘卡片）。
  • 页签下方为筛选区，一排展示两个下拉：
    · 时间筛选（默认「今天」）：今天 / 昨天 / 近7天 / 近30天 / 自定义；选择「自定义」弹出自定义时间弹窗（与买单已结算的筛选弹窗一致），应用后下拉文案显示所选区间；
    · 状态筛选（默认「全部」）：全部 / 卖出中 / 已售罄 / 已结算 / 已关闭。
  • 筛选区下方为四列汇总：总卖出 / 进行中 / 已消费 / 总结算盈亏（盈利绿色、亏损红色、不输不赢黑色，符号与数值同行不换行）。

私盘卡片字段

  • 联赛、「私盘」标识、状态标签、私盘名称（与赛事列表中该私盘的名称一致，即「原比赛名 · 庄家昵称」，不使用原比赛名）、盘号、开放项数、总押金、收单进度条、已收 / 押金、查看详情。
  • 私盘不展示分享按钮，暂不支持分享；投注项卖单的分享入口不受影响。
  • 卡片不展示「私盘」标识（私盘列表本身已表明来源）；已结算盘在该位置（联赛名右侧、状态标签左侧）展示盘净盈亏，赢绿输红、不输不赢黑色，带正负号且同行不换行。

历史数据

  • 上线前既有的投注项卖出庄单不受影响，自动归入「投注项卖单」分段。

开盘详情与控盘 · 需求标注

庄家对自己私盘拥有完整控盘能力：动态增减盘口、调水、单项封盘、补充额度、停止收单。

入口：我的卖出 → 私盘页签 → 点击盘卡片「查看详情」。庄家对自己私盘的全部控盘操作都在本页完成。

页面结构（自上而下）

  • 顶栏：返回（回我的卖出）、标题「开盘详情」、右侧盘状态标签（卖出中 / 已售罄 / 已结算 / 已关闭）。本页不提供分享入口。
  • 状态横幅：仅在已关闭时展示，提示「已停止收单，卖出单已从卖单簿下架，等待赛事结算，未消费押金结算后退回」。已结算不展示顶部横幅，盈亏在列表汇总与各投注项庄单的输赢标签上体现。
  • 赛事信息卡：主队 vs 客队、联赛 · 开赛时间、开盘时间、自动封盘设置（开赛前 N 分钟）。
  • 四列汇总：总押金 / 已收单 / 子单数 / 状态。
  • 投注项庄单列表：标题「投注项庄单(N)」，逐项展示卡片。
  • 底部操作区：盘级操作按钮，按状态变化（见下）。

庄单卡片字段

  • 投注项名 + 单项状态标签：单项状态跟随盘状态——盘为卖出中时各投注项均显示「卖出中」，盘为已售罄时各项均显示「已售罄」，盘已关闭时各项显示「已关闭」；单项被庄家手动封盘时该项显示「已封盘」，不随盘状态；盘已结算时标签改为该投注项的输赢结果（赢绿 / 输红 / 走水灰），不再显示「已结算」。
  • 庄单赔率：绿色显示。确认开盘后固定，不随官方赔率联动。
  • 官方当前赔率：仅作参考不参与计算；当庄单赔率低于官方赔率时追加红字「低于官方」提示（此时该档位已从卖单簿下架，不可成交）。
  • 已收金额、剩余可卖额度（标注「共享盘押金」，提示额度来自整盘共享池）。
  • 单项操作：调水、封盘 / 恢复、分享；无成交的盘口可移除。
  • 分享按钮按单项庄单状态判定：仅该投注项庄单处于「卖出中」（盘在售、该项未封盘、仍有剩余可卖额度）时展示；已售罄、已封盘、已关闭、已结算均不展示。与投注项卖出详情的规则一致。
  • 子单列表：标题「子单数据(N)」，默认收起，点击标题行展开 / 收起（右侧显示「展开 ⌄ / 收起 ⌃」）；每次进入详情页默认全部收起。无成交时显示「子单数据(0)：暂无成交」，不可展开。每笔两行——第一行「会员」标签 + 买家 ID + 成交金额 + 成交赔率；第二行成交时间 + 结算金额（已结算，赢绿输红；未结算显示「未结算」）。

底部操作区（按盘状态）

  • 卖出中 / 已售罄：展示「新增盘口」「补充额度」「停止收单」。
  • 已结算 / 已关闭：无任何控盘操作，底部操作区整条隐藏；返回统一走左上角返回按钮。

调水

  • 新庄单赔率 = 当前庄单赔率 + 调整点位；点位可为负，最多两位小数，新赔率必须大于 0。
  • 官方当前赔率仅作参考，不参与计算；庄单赔率确认后固定，不随官方联动。
  • 已成交子单按原成交赔率结算，调水只影响后续新成交。
  • 调水不影响已占用押金：已成交子单的押金占用按成交时的庄单赔率锁定，不随后续调水重算；剩余押金仅因新成交、补充额度、结算三类事件变化。
  • 实时生效、卖单簿实时重排；单项 10 秒内限调 1 次，超频拦截。
  • 调水频次与幅度：10 秒限频为单投注项维度，同一盘内不同盘口可各自独立调整；单次调整点位绝对值上限、以及调整后赔率的绝对上限由配置参数控制，超出即拦截，防止极端赔率。

封盘 / 恢复（单投注项级）

  • 封盘后该项档位从卖单簿下架、暂停收单，卖出单保留，官方档位不受影响；开赛前可随时恢复，二次确认后执行。
  • 整盘自动封盘（到点或开赛）等价于全部投注项同时封盘。
  • 自动封盘触发后该设置即失效，恢复开盘后不会被再次自动封盘；需重设才再次生效。

新增 / 移除盘口

  • 新增：盘进行中可从 IM 交集内未开放的盘口勾选新增，按新增时官方港盘赔率 + 上浮点位定价，共享押金池，无需追加押金（剩余押金为 0 时提示先补充额度）。
  • 移除：仅该盘口无任何成交时可移除；盘押金为共享池，不因移除变动、不退款。
  • 移除后开放盘口数仍需满足 ≥ min_items，低于门槛拦截并提示「如需清空请使用停止收单」。
  • IM 侧被动下架：某盘口被 IM 下架时该投注项自动置为已封盘并从卖单簿移除，已成交子单按 IM 返回结果处理；若开放项因此低于 min_items，盘不自动关闭、可继续收单（门槛只约束开盘与主动移除，不回溯被动变化），但该盘口不可再新增。

补充额度 / 停止收单（盘级）

  • 补充额度：输入一笔追加金额，实时预览追加后押金与新增预计可卖额度；追加进入共享池，全部盘口剩余可卖同步扩大，赔率与状态不变；已售罄追加后回到卖出中。
  • 停止收单：二次确认（明示不可逆）后全部档位立即下架、私盘从列表消失、盘置为已关闭；已成交子单正常结算，未消费押金结算后退回。

押金与结算

  • 庄单赔率 = 开盘时官方港盘赔率 + 上浮点位（加法，可为负），确认后固定。
  • 预计可卖额度 = 盘押金 ÷ 最高卖出赔率（最保守口径）。
  • 剩余押金 = 盘押金 + 补仓 − Σ(成交金额 × 对应庄单赔率)；各盘口实时可卖 = 剩余押金 ÷ 该项赔率，任一盘口成交同步收缩其他盘口额度。
  • 每笔子单占用 = 成交金额 × 庄单赔率，即最大赔付责任，保证不穿仓；剩余押金归零即整盘售罄。
  • 额度死区：某盘口实时可卖额度低于该玩法最小投注额时，该项置为不可买（展示为额度不足的锁定态），避免「显示有额度但买不了」；全部开放项均不可买时整盘转为已售罄。
  • 并发控制：可卖额度以服务端为准，同一盘的成交请求串行处理，额度校验与扣减在同一事务内完成，杜绝多盘口并发成交导致的超卖穿仓；校验失败提示「额度已被其他买家占用，请重新输入金额」。
  • 结算：子单按买家视角，庄单盈亏 = 子单结算总和 × (−1)；押金全额解冻退回，盈亏逐项入账。
  • 分段结算：按投注项所属时段分别结算。上半场玩法在上半场结束并由 IM 返回结果后即结算，对应子单的押金占用同步释放、剩余押金回升、其余盘口可卖额度随之扩大；全场玩法待全场结束结算。盘在全部开放项结算完成后整体转为已结算。
  • 赛事改期：以 IM 返回为准。IM 保留赛事仅变更开赛时间时，盘顺延继续收单，自动封盘按新开赛时间重算；IM 取消赛事时按赛事取消处理，子单全额退款、押金全额解冻。
  • 抽佣费率由 APISYS 下发，不在本系统配置；庄家按单净盈利抽佣，买家侧抽佣基数 = 购买 P2P 盈利 − 购买官方盈利，由结算系统扣除。
  • 费率异常兜底：APISYS 未返回费率或返回非法值（小于 0 或大于 100%）时不采用该值，按平台兜底费率（配置项）结算，并记录异常日志告警，不阻断结算。
  • 押金占用提示：开盘前常驻灰字「押金自开盘起冻结，至赛事结算后解冻退回」，早盘额外提示预计冻结时长。

私盘（自定义赛事）· 赛事大厅

本期做自定义赛事坐庄：脱离 IM 的自定义足球比赛，庄家填两队名与两队均进球数（即该队预计进球数），系统按 Poisson 比分模型生成全套盘口并按比分统一做市，赔率没有外部来源。下期做「复制 IM 既有赛事坐庄」，同样叫私盘。

入口与筛选

  • 独立联赛分组：自定义赛事没有 IM 母体，不挂在任何原比赛下方，在赛事列表顶部独立成「自定义赛事」分组，右侧带「私盘」标识，可折叠。
  • 「我要开盘」入口在「我的」页，位于「我的卖单」上方，不放在赛事列表的筛选行；开盘弹窗的完整需求见「我的」页标注。
  • 自定义赛事常驻置顶：不做「只看」开关、不占筛选行。分组固定在赛事列表顶部，带「私盘」标识、可折叠，下方接 IM 赛事，想看 IM 赛事往下滑即可。仅今日盘与早盘展示（自定义赛事只做赛前盘），且只有足球有，切到其他球类不展示。
  • 顶部区域：球类只留图标（不展示名称与数量），赛事数量移到盘口页签下方，并随当前选中球类变化。
  • 列表展示窗口：只显示已到开盘时间的赛事；开赛后继续展示 90 分钟，此时赛事已封盘，玩家仍可在列表找到并进入详情，但不能投注。超过 90 分钟从列表移除，庄家仍可在「卖单 → 私盘」管理。
  • 排序：按开赛时间正序排列。
  • 比赛行三列固定，与官方盘一致：全场独赢 / 全场让球 / 全场大/小；完整玩法进赛事详情查看，入口为队名下方的「全部 N▸」。列表行不展示比赛状态。
  • 行首结构：收藏 ☆ 在赛事名称左侧，开赛时间在赛事名称下方。赛事名称为庄家开盘时填写的名称。
  • 赔率格展示规则：整盘已售罄或单个投注项额度触顶显示「-」；已封盘及之后的状态（待审核 / 已结算 / 已关闭）显示锁图标；卖出中正常显示赔率。列表与详情一致，均置灰不可点击。

比赛状态（六个）

  • 卖出中：可买入。
  • 已售罄：押金占用触顶、接不了新注，赔率格置灰；补充额度后自动恢复为卖出中。这是资金层面的被动状态。
  • 已封盘：庄家或运营主动停止收单，其他玩家不能再购买该盘口，不可恢复。与已售罄是两回事。
  • 待审核：庄家已录入赛果，等待运营审核。
  • 已结算：审核通过，按赛果兑付，每份命中兑付 1 个结算单位。
  • 已关闭：运营强制下架（全部成交撤销、投注金额原路退回、不计盈亏），或开盘审核未通过（押金未冻结、本场直接关闭，庄家不能重新申请，需重新开盘）。

赔率格暂停态

  • 赔率降到平台最低赔率（默认 1.05），或本笔可投额度低于 5 时，该投注项暂停买入，格子置灰并标「暂停」。
  • 全部开放投注项都暂停时，整盘转为已售罄。额度回升自动恢复；暂停只影响买入。
  • 已售罄是动态状态，不是终态：押金占用取决于「最坏比分下的赔付」，当玩家买入反方向的投注项时，原本最危险的那个比分的净敞口被对冲、最大亏损下降，押金随之被释放，整盘可自动从已售罄回到卖出中，无需庄家补充押金。因此售罄后仍需持续计算敞口，不能简单锁死。补充押金同样可解除售罄。

本期玩法（八类）

  • 全场独赢、全场让球、全场大/小（可多线）、双重机会、双方进球、全场波胆、欧洲让球、主客队进球数。其中前三类开盘时必开。玩法名称与赛事列表保持一致。

定价原理（需求侧需要知道的）

  • 庄家只填两队均进球数（界面不出现 λ 这个符号），系统按独立 Poisson 生成比分矩阵，再把「在全部已开玩法下结算结果完全相同」的比分合并为比分状态，做市在状态层进行。
  • 投注项价格 = 其命中的全部比分状态价格之和。同一件事从不同玩法买到的价格必然相同，不存在跨玩法套利。
  • 同一玩法各投注项价格之和 = 1 + 溢价（默认 3%，按开盘概率分摊，平台统一配置）。
  • 显示赔率 = (1 − 抽水率) ÷ 价格，再按赔率封顶（默认 99）截取。抽水默认每万收 300，以压低赔率的方式收取，不从投注额里扣。
  • 本期有两处抽水，口径不同，不要混淆：
    · 玩家侧抽水（默认每万收 300，即 3%）——在每笔成交当下就以压低赔率的方式收取，玩家付 100 元、只有 97 元进入做市计算份额，账面上看不到单独的扣款。
    · 庄家侧抽水（比例由 APISYS 下发，演示 2%）——在结算时对庄家的盈利部分收取，亏损不收。
    · 赛事被强制下架时按投注金额全额退回，由于玩家侧抽水只是少给了份额、并非单独扣款，全额退回即自动包含该部分，平台在这类场次上不赚不亏；庄家侧抽水因未进入结算阶段，本就不会产生。
  • 玩家使用钱包余额下注，没有「期初余额」的概念。算法文档 5.5 节的期初筹码、沿用上一场期末余额、累计盈亏快照、排行榜，是单机模拟页的虚拟筹码玩法，本期不实现，研发不要照该节实现。

单笔限额怎么算

输入框里「限额 2.00-X」的 X，是下面三项取最小值，再向下取整到两位小数。三项各自防一种风险，缺一不可。

  • A 庄家设定的「单笔最多收」：开盘时填的固定值（默认 2000），是庄家对单笔规模的主观上限。
  • B 滑点上限对应的金额：做市下投得越多、买到的平均赔率越低，这个差距就是滑点（滑点 = 1 − 本笔实际赔率 ÷ 所见赔率）。系统反推出「让本笔滑点恰好等于滑点上限」的那个投注额。
    · 普通项滑点上限默认 5%。
    · 冷门项按比例放宽：当该项价格低于冷门线（默认 20%）时，上限从 5% 线性放宽，最多到 20%——冷门项本身盘薄，不放宽的话几乎投不进钱。放宽比例 = (1 − 当前价格 ÷ 冷门线)。
  • C 赔率触及最低赔率前的额度：系统反推出「把该项价格推到价格上限（对应平台最低赔率，默认 1.05）」所需的投注额。超过这个数，赔率就跌破下限了。

暂停条件：当前价格已达价格上限，或三项取最小后不足 5 元，该投注项暂停买入、格子置灰。全部开放投注项都暂停时整盘转为已售罄。

输入超限的处理：不直接拒绝，按上限试算并提示，玩家可自行改小。

购物车（沿用原有购物车，不另开面板）

  • 选中自定义赛事投注项直接进原购物车；卖出页签自动隐藏，做市成交不支持被其他会员卖出。关闭按钮保留。
  • 右上角增加清空按钮（关闭按钮左侧），点击直接清空购物车全部选项并关闭面板。
  • 卡片右上角是本笔实际成交赔率，随输入金额实时变动，后面紧跟差值「(低 X)」——差值 = 所见赔率 − 本笔实际赔率，以数值呈现、不用百分比。输入框上方一行对照展示所见赔率与成交后赔率（成交后赔率与本笔实际赔率取同值）。盘口类型标注为 [欧洲盘]。
  • 赛事信息行为「自定义赛事 · 赛事名称」。底部不展示串关按钮，自定义赛事不参与串关。
  • 所见赔率 > 本笔实际赔率恒成立。所见赔率是下单前该项的当前赔率（边际价）；本笔实际赔率是这笔钱买到的平均赔率，投注额越大越低。两者必须同口径（同样计入溢价与抽水），否则小额投注会算出「本笔高于所见」的矛盾结果。
  • 单笔上限直接作为输入框的限额提示（「限额 2.00-X」），不单独列字段。超额按上限试算，不直接拒绝。
  • 自定义赛事不参与串关。
  • 赢时可得不在购物车展示，在投注成功后的注单确认弹窗中以「可赢金额」呈现；注单确认弹窗不展示「获得份额」。注单确认与买单列表都展示赛事名称（买单为「自定义赛事 · 赛事名称」）。
  • 成交后赔率与本笔实际赔率取同一数值——玩家关心的是这笔按什么价成交，不需要再给一个推动后的理论价。
  • 赔率旁的差值以数值呈现（如「(低 0.15)」），不用百分比。
  • 玩家侧「最低接受赔率」本期去掉，购物车不再提供该输入框，相关文案一并移除。
  • 买单列表不与官方注单统一展示：官方注单是固定赔率、字段为「投注金额 / 最高可赢」；自定义赛事是做市成交、额外有「获得份额」，两者各按自己的口径展示，不合并成同一种卡片。已结算时自定义赛事同样展示输赢与比分，格式与官方注单一致。

调水与算法定价的关系

  • 调水不会架空算法。算法约束的不是赔率数值本身，而是赔率与风险敞口的绑定：赔率由持仓量决定，亏损上限由押金锁死。调水等效于庄家替市场推动了一次持仓，系统后续定价仍从新的持仓出发，不穿仓、跨玩法同价、价格随资金移动三条约束全部继续成立。
  • 跨玩法同价自动维持：调水改的是该投注项命中的全部比分状态，正确比分等相关玩法的价格会同步联动，不会出现「主胜调了、波胆没动」的套利缺口。这是按比分状态做市的结构性好处。
  • 调水的真实作用是调节吸单速度与敞口，不是绕过定价。实测：抬高赔率后玩家投入从 1675 增至 2175、押金占用从 16.7% 升到 49.3%；压低赔率则相反。庄家是在用押金使用效率换成交量。
  • 因此赛事列表的赔率跟随调水变化是正确的——那就是当前真实可成交的价格。

并发要求（必须写进研发需求）

  • 每笔成交都移动价格，同一场比赛的成交必须串行处理，价格读取与扣减在同一事务内完成。否则份额算错、押金保护失效，平台亏损可能突破押金。
  • 试算与成交之间价格若被他人推动，应以服务端实时价格重新计算，超出玩家可接受滑点时拒绝。

结算口径

  • 赛果只计常规时间 90 分钟（含补时），不含加时赛与点球大战。
  • 赛果比分超出模型球数范围时，按比分状态结算，任何非负整数比分都能结算。
  • 赛果由庄家录入、运营审核：庄家封盘后录入比分提交，比赛进入待审核；运营核对后通过则正式结算，审核通过前不发生任何资金兑付。本期不做平台抽水：庄家侧（结算时对盈利抽成）与玩家侧（成交时压低赔率）比例均默认 0，结算明细不展示抽水行；开盘弹窗保留配置项，后续启用改配置即可。本期不做撤销结算：结算后如发现赛果有误，走人工处理，不在 C 端提供撤销入口。
  • 允许庄家在自己创建的盘上下注，与普通玩家无差别，界面不做任何提示或限制。
    · 风险提示（需运营知悉，不在 C 端展示）：庄家同时拥有调水权与赛果录入权，自投打开后存在「先调水拉高赔率、自投后再压回」以及「按对自己有利的比分录入赛果」的操纵路径。缓解手段依赖后台：调水全程留痕（含调水时的已收单与敞口）、庄家自投的注单在后台标注、赛果审核时一并核验。

开盘详情（庄家管理视角）

仅从「卖单 → 私盘」页签进入，只有本人的盘能进。与赛事大厅进入的赛事详情是两个独立页面，各自单一职责：赛事详情只负责投注，开盘详情只负责管理。

页面结构

  • 顶栏：返回（回我的卖出）、标题「开盘详情」、右侧「操盘日志」入口（不带条数）。盘状态不放顶栏。
  • 赛事信息卡：主客队 +盘状态标签（在队名右侧）、赛事名称与开赛时间、开盘时间与封盘规则、两队均进球数、「本场全部注单」入口。被驳回时在队名下方展示红色驳回区块（只给标题与原因正文，不展示驳回人与时间）。
    · 开盘时未开启「按均进球数自动生成赔率」的盘，详情页不展示均进球数——手动定价的盘没有这个参数，展示出来会误导。
    · 均进球数仅在卖出中与已售罄可编辑，其余状态只读展示数值。改动后重算未成交部分的赔率，已成交子单按原成交赔率结算、不受影响。
    · 「本场全部注单」点击进二级弹窗，不设标题与说明文案，直接列出投注项、成交赔率、会员名、下注时间、下注金额（已结算时标明收入或赔付）；每页 20 条，下拉到底自动加载下一页，区域约占屏高 62%。
  • 三列汇总：总押金 / 已收单 / 子单数；已结算时增加第四格本场净盈亏。不展示「押金占用」——该值依赖最坏比分试算，对庄家不直观。汇总区紧贴赛事信息卡，减少顶部占位。
  • 子单数做成超链接（橙色带下划线），点击弹出本场全部子单；不再单独设「本场全部注单」入口行。
  • 不单独设结算明细区块——已结算时顶部汇总的第四格已展示本场净盈亏，再列一遍收到投注、命中兑付是重复信息；明细口径仍为「收到投注合计 − 命中兑付合计 = 本场净盈亏」，押金全额解冻退回，本期不计平台抽水。
  • 比分风险分布：一行标签展示「风险最高」前 3 项 +「更多 ›」，点击弹出 7×7 表格块。仅卖出中与已售罄展示，其余状态不展示（已不能调水，看风险分布无意义）。
    · 这张表是本场盈亏金额，不是概率：格子里的数字是「该比分真开出来时，本场赚多少或赔多少」＝ 已收投注 − 命中该比分的全部投注项赔付，亏损为红色、颜色越深亏得越多。它回答的是「我最怕开出哪个比分」。
    · 与开盘弹窗的比分概率分布结构、文案保持一致，只是数据不同：标题「比分风险分布」+ 副标题「均进球数 X / Y · 单位 CNY」+ 7×7 表格（行为主队进球数、列为客队进球数，最后一档为 6+），弹窗左右不留白、占满宽度。
    · 每个标签只展示一个比分，不做比分合并。做市内部会把结算结果相同的比分合并成「比分状态」，但展示上必须拆开到单一比分，否则会出现「0:4 0:5 等」这种一个标签多个比分，庄家读不出到底怕哪个。只有两个比分的金额恰好相同时才会并列出现（各占一个标签）。
    · 金额缩写规则（格子窄，必须缩写）：绝对值 ≥ 10000 用「w」、≥ 1000 用「k」，各保留一位小数且去掉末尾的 .0；小于 1000 取整直接显示。例：45 → 45，1234 → 1.2k，−4538 → −4.5k，28500 → 2.9w，−123456 → −12.3w。
  • 玩法选项卡：风险分布下方横向排列，tab 分页——「全部 / 各玩法」，切换后只展示该玩法的庄单卡片。选项卡只展示玩法大类名称（独赢 / 让球 / 大/小 / 双重机会 / 双方进球 / 波胆 / 欧洲让球 / 进球数），多条盘口线的玩法合并为一项，不把每条线或每个投注项都排进去。「投注项庄单」这个标题不展示。
  • 底部固定操作区按状态变化。

庄单卡片字段

  • 玩法 · 投注项名；已结算时右上角展示输赢标签，单项被封盘时展示「已封盘」，其余状态不展示标签（盘状态在赛事信息卡内展示一次）。
  • 输赢一律用「赢 / 输」表示，不用「命中 / 未命中」「收入 / 赔付」，但两处立场不同：
    · 投注项卡片与赛事卡片站卖家（庄家）立场：标签由该投注项下全部子单的盈亏之和取反得出——子单赢多少，庄家就输多少。盈亏为负显示输（红），否则显示赢（绿）。没有子单的投注项无论是否命中赛果都显示赢（庄家没在这项上赔钱）。
    · 子单列表站买家（玩家）立场，卡片内展开的子单与子单弹窗口径一致：该笔命中 → 玩家赢（绿），金额为兑付额 − 投注额；未命中 → 玩家输（红），金额为投注额。
    · 同一场里两处标签会相反，这是对的——庄家与玩家本就是对手盘。
  • 赔率对比行：当前赔率（绿色大字）、开盘赔率、偏离百分比（涨绿跌红）。调水要判断的是当前价位相对开盘偏了多少，直接给出幅度比让庄家自己换算更可用。
  • 已收、命中需赔、本笔上限；额度触顶时提示「该项额度已触顶，暂停买入」。
  • 子单数据默认收起，点击标题行展开；每笔展示买家、金额、份额、成交赔率、成交时间；已结算时右侧展示该笔的输赢金额，已强制下架时展示退回金额。
  • 赔率行即操作区，与封盘同一行：「当前赔率」字段名 + 一体化的「－ 数值 ＋」控件 + 开盘赔率 + 封盘按钮。数值可直接输入目标赔率（回车或失焦生效），也可用 －/＋ 按 0.01 步进。开盘赔率后不展示偏离百分比。不提供投注项级分享与移除，分享只在赛事层面提供。
  • 调水仅在卖出中与已售罄可用，其余状态赔率只读、不展示封盘按钮；界面与函数两层都做了拦截。
  • 同玩法其他投注项会跟着反向变动，这是正确行为：做市下同一玩法各项价格之和恒为 1+溢价，只改一项会破坏该恒等式、产生套利空间。跨玩法同理——调高「主胜」会让波胆里所有主队赢的比分赔率一起降，因为它们命中同一批比分状态。测试时不要当作 bug。

自定义赛事完整生命周期

  • ① 庄家开盘：填赛事信息、玩法与盘口线、押金，提交后进入待审核，押金在提交时即冻结。审核通过则上架；未通过则直接转为「已关闭」、押金退回，驳回原因在盘详情的队名下方展示，庄家不能重新申请，需重新开盘。
  • ② 上架收单：进入赛事列表，玩家可投注。盘状态在卖出中与已售罄之间自动切换（押金占用触顶即售罄，补充押金后恢复）。庄家可调水、补充押金、主动「赛事下架」。
  • ③ 自动封盘：到达开赛前 5 分钟（写死，庄家不可配置）系统自动封盘、停止收单，状态转为已封盘。庄家主动「赛事下架」也进入该状态。封盘后均进球数与赔率均不可再改。
  • ④ 庄家录入赛果：比赛结束后，庄家在开盘详情底部点「录入赛果」，填入常规时间 90 分钟（含补时）比分并提交，状态转为待审核。卖单列表该盘卡片上提示「比赛已结束，请录入赛果」。
  • ⑤ 运营审核：后台核对公开赛果，通过则正式结算；不通过时盘仍为待审核，底部按钮变为「重新录入赛果」，庄家按驳回说明改正后重新提交，重提后清除上一次的驳回信息。审核通过前不发生任何资金兑付。
  • 驳回原因的展示：运营在后台驳回时填写原因，展示在开盘详情的赛事信息卡内、队名下方的红色区块里，只给标题（开盘审核未通过 / 赛果审核未通过）与原因正文，不展示驳回人与驳回时间。
    卖单列表卡片不加驳回标识，只在卡片内给一行红色提示，不展示原因正文——列表只负责让庄家知道哪条需要处理，具体原因进详情看。不依赖客服通道。赛果被驳回时状态标签为「待审核」、提示「赛果被驳回，请进入详情查看原因并重新录入」；开盘被驳回时状态标签为「已关闭」、提示「开盘未通过审核，本场已关闭，如需继续请重新开盘」。
  • 状态对外收敛：开盘待审核、赛果待审核、赛果被驳回三种内部情形，对庄家统一显示为「待审核」，筛选项里也只有一个「待审核」并涵盖这三种，区别只体现在详情页的驳回区块与底部按钮上。开盘被驳回是例外——它直接转为「已关闭」，押金退回，庄家不能重新申请、需重新开盘。
  • ⑥ 已结算：按赛果兑付子单，押金解冻退回，盘详情展示结算明细与本场净盈亏。
  • 异常路径：比赛取消、延期超 48 小时、腰斩后 48 小时未恢复，由运营强制下架（与 B 端叫法统一），状态转为已关闭，全部成交撤销、投注金额全额原路退回（含玩家在成交时已付的抽水）、庄家押金全额解冻、本场不计盈亏、不抽庄家的水。本期不做撤销结算，已结算的盘如发现赛果有误走人工处理。

控盘操作

  • 调水：在庄单卡片的赔率行直接操作，不开弹窗。
    · 结构为「当前赔率 + 一体化的 － 数值 ＋ 控件 + 开盘赔率 + 封盘按钮」，同一行。数值框可直接输入目标赔率（回车或失焦生效），也可用 －/＋ 按 0.01 步进。
    · 展示开盘赔率作参考（自定义赛事没有官方盘可参照），不展示偏离百分比。
    · 新赔率需落在该盘设定的最低赔率与最高赔率之间，越界时提示并不执行。
    · 仅卖出中与已售罄可调水，其余状态赔率只读、不展示封盘按钮。
    · 做市定价下调水等效于庄家推动该投注项价格，同玩法其他项赔率同步反向变动；已成交子单按原成交赔率结算，不受影响。
    · 幅度闸门：单次调水不超过 0.05，单个投注项累计调水（历次绝对值之和）不超过 0.30。弹窗实时显示「单次上限 0.05 · 本项累计剩余 X / 0.30」，超限时提示原因并禁用确认按钮。没有闸门时庄家可一次把赔率从 1.93 拉到 5.36，既不合理也容易被当成操纵。
    · 操盘日志：入口在开盘详情顶栏右侧（不带条数）。记录调水、封盘、补充押金、赛事下架四类操作，各带类型色标。每条都要留下数据——调水记录玩法投注项与调整前后赔率、封盘记录玩法、补充押金记录追加金额、赛事下架记录操作本身，统一附当时的已收金额与子单笔数。每条两行：类型标签 + 对象 + 变动值，下一行时间 + 赔率变化或已收金额。不记录庄家名称与押金占用。
    · 弹窗顶部一排筛选胶囊：全部 / 调水 / 封盘 / 补充押金 / 赛事下架，各带条数，点击按类型过滤；该类型无记录时给空态提示。运营在后台也能核查。庄家可在自己盘上下注，存在「先低价买入再调高赔率诱多」的操纵路径，因此调水与庄家自投都必须留痕。
  • 立即封盘：以玩法为单位。做市定价下同一玩法内各投注项共享同一条价格曲线，单独封掉其中一项会破坏跨玩法同价、产生套利空间，因此封盘必须整个玩法一起封。
  • 分享：分享该玩法及其投注项赔率到金刚，接收方进入本场赛事详情并定位到该玩法。
  • 移除：仅该玩法无任何成交时可移除。移除会改变比分状态的合并方式，其余玩法赔率随之重算；已成交份额按原成交赔率结算不受影响。
  • 补充额度：追加押金后本场最大亏损上限提高，盘口流动性同步加深（同样金额对赔率的推动变小），当前赔率保持不变；已售罄的盘补充后自动恢复为卖出中。
  • 停止收单：整盘封盘，二次确认后不可撤销；已持有份额的玩家不可卖出，等待录入赛果。
  • 录入赛果：庄家填入常规时间比分并提交，盘转为待审核，由运营核对后结算。

底部操作区（按状态）

  • 卖出中 / 已售罄：补充额度 / 停止收单。
  • 已封盘：录入赛果。
  • 待审核：展示等待审核提示，无操作按钮。
  • 已结算 / 已关闭：整条隐藏，返回走左上角返回按钮。

我的 · 需求标注

本期与自定义赛事相关的改动有两处：「我要开盘」入口（位于「我的卖单」上方）与汇总报表的统计范围。其余分组沿用既有实现。

我要开盘（入口在本页，位于「我的卖单」上方）

  • 赛事信息：赛事名称、主客队名与队徽、开赛时间与开盘时间（并排，均必填）、赛事直播地址（选填）。开盘时间字段名后带 ⓘ，说明开盘时间、封盘时间（固定开赛前 5 分钟）与列表展示窗口（开赛后 90 分钟）。
  • 队徽支持上传图片：点队徽方块弹出选择面板，上方为上传区（支持 PNG / JPG，建议正方形，不超过 2MB），下方保留内置图标供快速选择。已上传图片时可「移除图片，改用图标」。上传后在表单与赛事列表、详情中按图片展示。
  • 赔率生成方式：开关「按均进球数自动生成赔率」，ⓘ 紧跟开关名。
    · 开启：填两队均进球数（该队在这场预计能进几个球，0.1~6）。ⓘ 里重点解释为什么可以是小数——它不是「这场一定进几个」，而是平均下来能进几个；足球进球少，一两个球的差别对赔率影响很大，必须用小数才描述得准。下方一行展示最热比分前三项与「更多 ›」，点击弹出 7×7 比分概率分布表格块。
    · 这张表是概率占比，不是投注金额：格子里的数字是该比分出现的可能性（单位 %，全表合计约 100%），颜色越深越可能出现。它回答的是「按我填的均进球数，这场最可能踢成几比几」。
    · 弹窗结构：标题「比分概率分布」+ 副标题「均进球数 X / Y · 单位 %」+ 7×7 表格（行为主队进球数、列为客队进球数，最后一档为 6+）。
    · 关闭：所有赔率由庄家手动填写，赔率不随成交变动。此模式脱离做市模型，需要两层独立风控，见下条。
  • 手动定价模式的风控（两层，缺一不可）：自动模式下由做市结构自动成立的三条保证——同玩法价格和恒等、跨玩法不套利、亏损不超押金——在手动模式下全部失效。
    · 第一层，提交开盘时的静态校验：同玩法各项赔率的隐含概率之和（Σ 1÷赔率）必须 ≥ 覆盖重数 ×（1 + 最低溢价 2%），低于此值说明这组赔率对庄家不利到可被玩家全买套利，拦截提交并指出是哪个玩法、当前和值多少、要求达到多少。
    · 覆盖重数 = 每个赛果同时被该玩法的几个投注项覆盖。独赢、让球、大小球、波胆、欧洲让球、进球数、双方进球都是互斥穷尽，重数 1、阈值 1.02；双重机会的三项（主或平、主或客、平或客）中每个赛果被其中两项覆盖，重数 2、阈值 2.04。若对双重机会沿用 1.02，校验等于没做——它的和值本来就在 2 左右，任何填法都能通过。
    · 手动模式不提供波胆：玩法列表里直接不展示，从 8 类减为 7 类。波胆是最细粒度玩法，其他玩法都能用它的组合复制；自动模式下所有赔率来自同一张比分概率表、无套利是算出来的，手动模式下庄家逐项填赔率、系统无从保证自洽。又因独赢/让球/大小球三类必开、在手动模式下一定存在，波胆与它们同开必然冲突、等于永远开不了，所以直接不展示而非置灰。从自动切到手动时若已勾选波胆则自动关闭并提示。
    · 押金下限：押金 ÷ 该盘最大赔率 ≥ 2 元，确保押金不至于小到开不了盘。
    · 第二层，每笔成交前的押金硬上限：枚举主客各 0~6 球加「其他比分」共 50 个状态，算出最坏赔付（Σ 命中该比分的投注项的 已售份额 × 赔率），净敞口 = 最坏赔付 − 已收投注总额；净敞口超过押金即拒绝本笔。拒单时不直接拒绝，反推出恰好不突破押金的最大金额并提示，玩家可改小。
    · 举例：押金 1000、主胜赔率 2.5，该项单笔上限为 666.66——买满后最坏赔付 1666.65、已收 666.66、净敞口 999.99，恰好不超押金；此时该项自动暂停买入。
    · 单笔上限在手动模式下为两项取最小：单笔最多收、押金硬上限（赔率固定，无滑点与最低赔率限额）。已售罄判定改为全部投注项的押金硬上限都不足 5 元。调水语义变为直接改该项赔率，改完需重算最坏赔付，若导致已有持仓突破押金则拒绝调整并提示先补充押金。
    · 残留风险：跨玩法套利仅靠「手动模式不提供波胆」规避，属经验性限制而非数学保证——其他玩法之间仍可能存在局部等价关系。若后续要放开波胆，须先补完整的等价组合校验。
  • 赔率限制与抽水（紧接均进球数下方）：最低赔率、最高赔率、抽水三项并排，每个字段名后各带一个 ⓘ，分别说明——最低赔率是压价保护线（触及该值该项自动暂停收单）、最高赔率是冷门项的展示上限、抽水是每万抽多少且不从投注额扣而是少给份额。
  • 开放玩法（8 类）：全场独赢、全场让球、全场大/小、双重机会、双方进球、全场波胆、欧洲让球、主客队进球数。
    · 前三类必开：不给开关，原开关位置直接显示橙色「必开」二字。
    · 玩法区上方有玩法选项卡（tab 分页）：「全部 / 各玩法」，切换后只展示该玩法的配置块；已开启的玩法在选项卡上带 ✓。
  • 盘口线配置放在该玩法赔率格上方，枚举全列、横向滑动不换行，点击选中或取消，不提供输入框与添加按钮：
    · 选项多时自动换行展示，不做横向滚动（滚动找选项不方便）。
    · 全场让球：主 +4.5 ~ 主 −4.5 共 10 档半球线（只用常用区间，不做到 ±9.5），换行后约占两排。
    · 全场大/小：0.5 ~ 7.5 共 8 档。
    · 欧洲让球：1 ~ 5 的整数。
    · 全场波胆：互斥单选，2 球 ~ 7 球共 6 档，决定逐项列出到几球（标签不带「0~」前缀）。
    · 主客队进球数：可多选，0 球 ~ 7 球共 8 档，最后一档自动变成「N+ 球」。
    · 每类至少保留一项，最后一项不可取消，如需关闭该玩法请用玩法开关。
    · 盘口线上方不再展示灰色的玩法名（如「全场 让球 主 +3.5」）。
    · 盘口线配置与均进球数开关无关：它决定「开哪些投注项」，赔率怎么生成是另一回事，自动模式下照常为新增的线生成赔率。
  • 押金与收单放在顶部设置区，紧接在最低赔率 / 最高赔率 / 抽水那一行下方，与它们同一张卡，不被玩法配置隔开：押金金额（≥100）、单笔最多收（默认 2000），两个字段名后各带 ⓘ 说明——押金是本场最大亏损上限且决定盘口深度、单笔最多收防止一笔大单打穿某个方向。
  • 必填校验按字段就地提示：刚打开不标红；字段被编辑过或点过提交后，不合法字段边框变红、下方给一行红色说明。
  • 「提交申请」按钮固定在弹窗底部，不随内容滚动，表单再长也始终可见。按钮上方一行说明：提交后需运营审核，通过才上架；押金在提交时冻结，未通过则退回。

汇总报表需包含私盘数据

  • 入口：我的 → 汇总报表。本期新增要求——报表的统计范围必须包含私盘（自定义赛事），不能只统计买单与投注项卖单。
  • 总盈亏 = 买单盈亏 + 卖单盈亏 + 私盘盈亏。三者都是已扣除平台抽佣后的净额，量纲一致可相加。
  • 按日明细表新增「私盘盈亏」一列，表头为：日期 / 买单输赢 / 卖单盈亏 / 私盘盈亏 / 合计。
  • 展开某一日时，在买单、卖单两组之后新增一组「私盘（自定义赛事）」，字段为：结算场次、收到投注、平台抽水、押金合计、子单笔数、本日盈亏；底部提供「查看私盘 ›」跳转到「卖单 → 私盘」页签。当日无私盘结算时该组不展示。
  • 私盘盈亏的计算与开盘详情的结算明细同源：收到投注合计 − 命中兑付合计 = 盈亏小计，盈利部分按 APISYS 下发比例抽水后得净盈亏。报表与详情不得各算各的。
  • 归集口径与既有一致：按结算时间归集，只统计已结算的私盘；进行中（卖出中 / 已售罄 / 已封盘 / 待审核）的私盘只计入顶部的当前快照，不计入盈亏、不随时间筛选变化。
  • 押金与投注额不可相加，不设「总投入」这类合并指标。
