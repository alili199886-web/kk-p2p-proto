第 1 章 总览

1.1 背景与目标

为什么做。 平台用 USDT 开足球预测盘，玩家买卖比赛结果的「份额」，每份在投注项获胜时兑付 1 USDT。平台没有外部赔率可以参考：开盘价只能来自庄家对两队场均进球的估计，之后要靠玩家资金把价格推到合理位置。由此产生三个必须同时满足的约束：

  1. 每场亏损有上限：任何比分开出，平台在这场的亏损都不超过庄家设的抵押金。
  2. 不能被套利：同一件事（例如「主队净胜 2 球及以上」）可以从胜平负、让球、欧洲让球、正确比分等多个玩法买到，这些入口必须永远同价，玩家无法组合出「任何比分都赚」的买法。
  3. 价格随资金移动：买的人多，价格上涨、赔率下降；盘口开始浅，成交越多越深。

不解决的后果。 2026-11-18 用旧的「按玩法分别定价」做模拟：120 次中 120 次出现跨玩法稳赚组合，套利机器人 117/117 次锁定利润。加交易前套利检查虽能拦住，但玩家投注额只剩 79%，一边倒时 3000 笔里被拒 1600～2000 笔。因此本 PRD 只保留「按比分统一做市」一种定价。

第 2 章 比分概率模型、玩法与结算

本章定义三件事：一场比赛每个比分的概率怎么算（2.1）；每个玩法的每个投注项在哪些比分下获胜（2.2、2.3）；哪些比分在全部已开玩法下结算完全相同、因此合并为一个比分状态（2.4）。价格、赔率、单笔上限的计算见后续章节，本章只在需要说明影响时引用其结果。

本章计算举例除注明外使用默认盘（配置见 1.6）。

2.1 比分概率模型

2.1.1 规则

R2.1-1 比分概率按独立泊松分布计算。 庄家输入主队、客队本场的预计场均进球 λH、λA。主队进 i 球、客队进 j 球的概率为：

P(i, j) = Pois(i; λH) × Pois(j; λA)，其中 Pois(k; λ) = e^(−λ) × λ^k / k!

两队进球数互相独立，不做相关性修正（不引入 Dixon-Coles 等低比分修正项）。

R2.1-2 比分矩阵的范围。 系统只计算 0～G 球的比分，共 (G+1)² 个比分。G 按以下顺序确定：

  1. 起点 G = max(maxGoals, csMax + 1)。
  2. 令 λmax = max(λH, λA)。若 2 × P(X > G | λmax) ≥ 1e-9（X 服从泊松分布），则 G 加 1，重复判断，直到条件不成立或 G 达到 60。
  3. 得到的 G 称为「实际球数」（实现对照：effectiveGoals）。

第 2 步的含义：落在矩阵外的概率不超过 2 × P(X > G | λmax)，规则保证这个上界小于 1e-9。

实现对照：模型页（自定义球盘模型.html）把模拟用的「真实λ」也纳入 λmax；投注模拟页把真实λ设为庄家 λ，两者结果一致。真实λ只是模拟假设，不进入生产规则。

R2.1-3 截断后的归一化。 矩阵内全部比分概率之和 = 1 − 截断概率；系统把每个比分概率除以这个和，使矩阵内合计恰为 1。由于 R2.1-2 已把截断概率压到 1e-9 以下，这一步对任何比分概率的影响小于 1e-9。

R2.1-4 为什么不能用小矩阵再按比例归一化。 若只算到较小的 G（例如 4 球）再归一化，被截掉的高比分概率会按比例摊回给低比分：低比分被高估，「其他比分」、大小球高线的「大」、受让方大比分落后等高比分事件被低估，对应投注项的开盘赔率偏高，平台按偏高的赔率接单。所以 maxGoals 只是下限，实际球数必须按 R2.1-2 扩展，不允许用「截断 + 归一化」代替扩展。

2.1.4 异常与边界

  • λH 或 λA 不大于 0、不是数字（含输入框留空）：保存设置时报错，设置不保存。报错文案：
  • 模型页：「主队 λ 须为大于 0 的数」（客队为「客队 λ 须为大于 0 的数」）。
  • 投注模拟页：因真实λ设为庄家 λ，同一错误会再报一次真实λ，实际显示「主队 λ 须为大于 0 的数；真实λ 主队 须为大于 0 的数」。
  • λ 大于 15：报错「λ 不超过 15」。
  • λ 合法但过于极端时开不了盘：任一投注项开盘概率不大于 1e-12 时，系统报错「{玩法}「{投注项}」开盘概率为 0，LMSR 无法开盘；请调整盘口线或正确比分范围」，设置不保存。实测 λH = λA = 15 时报「正确比分「0:0」开盘概率为 0」；λH = λA = 0.3、csMax = 6 时报「正确比分「6:6」开盘概率为 0」。
  • 比分状态的开盘概率不大于 1e-15 时报错「有比分状态的开盘概率为 0，无法开盘；请调整盘口线」。
  • maxGoals 不是 4～30 的整数：报错「比分矩阵最少进球须为 4 ~ 30 的整数」。
  • 扩展上限：G 最多到 60。λ 取上限 15 时扩展到 G = 44 即满足截断上界小于 1e-9（G = 60 处上界为 3.1e-15），60 只作防护，合法 λ 下不会触达。
  • 结算比分超过实际球数 G：投注模拟页拒绝结算，提示「比分超过模型范围（G 球）」。见决策 Q2。

2.2 玩法目录与结算规则

2.2.1 总规则

R2.2-1 结算只看全场比分 (i, j)。 i = 主队进球，j = 客队进球。每个投注项在每个比分下要么全赢、要么全输，不存在走盘退款、半赢半输。

R2.2-2 每个市场在每个比分下恰好一个投注项获胜。 一个玩法按盘口线拆成多个市场（如大小球 1.5、2.5、3.5 是三个市场）。建盘时系统对每个市场、每个比分检查：若某比分下没有投注项获胜或多于一个投注项获胜，建盘失败并报错「市场 {id} 在比分 i:j 下没有获胜项 / 有多个获胜项」（实现对照：buildScenarios）。按本节的盘口线合法值（R2.2-5），这个错误不会出现，它是防止配置漏洞的兜底。

R2.2-3 兑付。 比赛结算比分为 (i, j) 时：获胜投注项的每一份份额兑付 1 USDT；其余投注项兑付 0。

2.2.4 计算举例

例 2.2-1 比分 2:1 下各市场的获胜投注项（默认盘，10 个市场）：胜平负 = 主胜；大小球 1.5 = 大 1.5；大小球 2.5 = 大 2.5；大小球 3.5 = 小 3.5；双方进球 = 是；正确比分 = 2:1；让球 主-1.5 = 客 +1.5；让球 主+1.5 = 主 +1.5；欧洲让球 主-1 = 让后平；欧洲让球 主+1 = 让后主胜。

二期玩法同一比分：主队进球 0.5 = 主队大 0.5；客队进球 0.5 = 客队大 0.5；主队进球 1.5 = 主队大 1.5；客队进球 1.5 = 客队小 1.5；主队零封 = 否；客队零封 = 否；主胜或平 = 是；主胜或客胜 = 是；平或客胜 = 否。

例 2.2-2 唯一获胜校验规模：默认盘 10 个市场 × 225 个比分 = 2250 次检查，每次恰好一个投注项获胜。默认盘共 10 个市场、38 个投注项；全部二期玩法也打开后为 19 个市场、56 个投注项。

2.2.5 异常与边界

  • 大小球线 0.5：合法；「小 0.5」与正确比分「0:0」是同一事件（开放建议见 2.3）。
  • 大小球线 9.5、让球线 ±5.5、欧洲让球 ±5、进球数线 5.5：合法上限，可建盘，但会新增冷门比分状态并开出暂停项（实测默认盘大小球线改为 0.5、1.5、2.5、3.5、9.5：比分状态 30 个，开盘即暂停 3 项：「大 0.5」1.0227、「小 9.5」0.9471、「主 +1.5」1.0471）。
  • 欧洲让球线写成 ±5.5：报「须为非 0 整数」，不是「超过」。
  • 让球线 ±0.5：合法；「主 -0.5」= 胜平负主胜，「主 +0.5」= 双重机会「主胜或平 是」。
  • 正确比分 csMax 与 maxGoals：实际球数 G 至少为 csMax + 1，「其他比分」概率不会为 0。
  • 投注模拟页中，旧比赛设置里没有让球（半球）、欧洲让球或二期玩法字段的，一律按关闭处理，已成交投注的结算不变。

2.2.6 验收标准

  • 1. Given 默认盘，When 比赛以 2:1 结算，Then 获胜投注项与例 2.2-1 一致，每个市场恰好 1 项获胜。
  • 2. Given 默认盘，When 遍历 0～14 球的全部 225 个比分，Then 10 个市场在每个比分下都恰好 1 个投注项获胜。
  • 3. Given 欧洲让球线 -1，When 比赛以 2:1 结算，Then「让后平」获胜，「让后主胜」「让后客胜」兑付为 0，不退本金。
  • 4. Given 正确比分 csMax = 3，When 比赛以 4:0 结算，Then「其他比分」获胜；When 以 3:3 结算，Then「3:3」获胜、「其他比分」兑付为 0。
  • 5. Given 玩家持有某投注项 10 份，When 比赛结算且该投注项获胜，Then 兑付 10 USDT；该投注项未获胜时兑付 0。
  • 6. Given 大小球线填 2.5、2.5，When 保存设置，Then 报错「大小球盘口线 2.5 重复（与 2.5 生成同一市场）」，设置不保存。
  • 7. Given 半球让球线填 -1，When 保存设置，Then 报错「让球（半球） -1 须为 .5 线（如 -1.5、+1.5）」。
  • 8. Given 欧洲让球线填 0，When 保存设置，Then 报错「欧洲让球 0 须为非 0 整数（如 -1、+1）」。
  • 9. Given 大小球线填 10.5 且欧洲让球线填 6，When 保存设置，Then 一次显示「大小球盘口线 10.5 超过 9.5；欧洲让球 6 超过 ±5.5」。
  • 9a. Given 大小球线填 10.5 且关闭全部玩法，When 保存设置，Then 只报「至少开一个玩法」（大小球已关闭，其盘口线不校验）。
  • 10. Given 全部玩法都不勾选，When 保存设置，Then 报错「至少开一个玩法」。
  • 11. Given 默认盘，When 建盘，Then 开盘即暂停列表只有「让球 主+1.5「主 +1.5」」一项，引擎赔率 1.0450；投注模拟页按两位小数截断显示，提示「开盘即暂停 1 项：让球 主+1.5「主 +1.5」（赔率 1.04），建议换线」。

2.4 比分状态合并

2.4.1 规则

R2.4-1 比分状态的定义。 对矩阵内每个比分 (i, j)，取它在全部已开市场下的获胜投注项，组成一个「结算签名」。结算签名完全相同的比分合并为一个比分状态（实现对照：setupScoreMaker）。比分状态的模型概率 = 其包含的全部比分模型概率之和。

R2.4-2 投注项 = 一组比分状态。 每个投注项对应它获胜的那些比分状态。结算时，结算比分所在的比分状态里获胜的投注项兑付，与 R2.2-3 等价。

R2.4-3 比分状态随已开玩法与盘口线变化，不随 λ、maxGoals 变化。 比分状态数只由已开玩法、盘口线、csMax 决定；改 λ 或 maxGoals 只改变每个状态包含多少个比分和状态概率，不改变状态数（实际球数 G 不小于 csMax + 1 且覆盖所有线的前提下）。

R2.4-4 重复投注项。 两个不同市场的投注项对应完全相同的比分状态集合时，称为重复投注项。重复投注项在业务上是同一个事件：

  • 任何时刻价格、赔率相同；
  • 从任一入口买入，对盘口、份额、各比分兑付的影响完全相同，换入口不会得到更好的价格，也不会放大单笔上限；
  • 以后若加「每个玩家每个投注项的累计限额」，限额须按比分状态集合计算，不能按「市场 + 投注项代码」计算，否则换一个重复入口即可绕过。

3.2 做市函数

3.2.1 规则

做市函数采用流动性敏感 LMSR（LS-LMSR），溢价按开盘概率加权分摊。记 q_i 为比分状态 i 的做市份额，N 为比分状态数。

R3.2-1 ～ R3.2-4 公式

R3.2-1  流动性参数   b = α · Σ β_i · q_i
        成本函数     C(q) = b · ln Σ exp(q_i / b)
R3.2-2  状态价格     p_i = w_i + α · β_i · H
                     w_i = exp(q_i / b) / Σ exp(q_j / b)
                     H   = Σ w_j · (ln Σ exp(q / b) − q_j / b)      （价格分布的熵）
R3.2-3  溢价分摊     prob：β_i = N × 该状态开盘概率（Σ β = N）
                     flat：β_i = 1
R3.2-4  α            α = 溢价 / (N · ln N)
        价格之和     Σ p = 1 + α · Σ β_i · H ≤ 1 + 溢价
  • R3.2-4 的含义：溢价是价格之和超出 1 的上限；实际开盘溢价 = α · N · H（prob），随开盘概率分布的熵变化。
  • R3.2-5 成交使 Σ β_i · q_i 增大 → b 增大 → 同样金额推价更少（盘口变深）。卖出反之。
  • R3.2-6 路径无关：同一组成交无论拆成几笔、按什么顺序，最终做市状态、玩家总份额、平台现金都相同。
  • R3.2-7 溢价 = 0 时退化为固定 b 的 LMSR：b = 抵押金 / ln(1 / 最冷比分状态开盘概率)，价格之和恒为 1。
  • R3.2-8 溢价被自动降低的条件与表现：
  • 平均分摊：若按设定溢价无法让每个状态按开盘概率开盘，系统把 α 降到可行上限的 90% 开盘。
  • 按概率分摊：若最冷状态的开盘份额会 ≤ 0，同样降到可行上限的 90%。
  • 被降后的溢价上限 = α · N · ln N。
  • 模型页（自定义球盘模型.html）显示「设定 X%，按当前比分状态开不了盘，已自动降到 Y%」；庄家后台（投注模拟页）目前不显示（见决策 Q10）。

4.1 单笔上限

4.1.1 规则

  1. 上限公式：某投注项当前的单笔上限 = min(A, B, C, D)。
  2. A = 单笔最多收；
  3. B = 滑点恰好等于该项「适用滑点上限」时的投注额（4.2）；单笔滑点上限设为 0 时 B 不限；
  4. C = 把该项价格推到平台最低赔率对应价格所需的投注额（4.3）；平台最低赔率设为 0 时 C 不限；
  5. D = 固定赔率模式下的抵押金硬上限（4.6）；LMSR 开启时 D 不参与。
  6. 上限来源：取最小值的那一项为上限来源，记为「单笔最多收 / 滑点 / 最低赔率 / 抵押金」。多项相等时按 A → B → D → C 的顺序，只有严格更小才替换来源。
  7. 超过上限按上限成交，不拒单：请求金额 > 单笔上限时，按单笔上限成交，剩余部分不成交、不扣款；请求金额 ≤ 单笔上限时按原额成交。唯一的例外是上限为 0（该项暂停买入，见 4.3；或固定赔率模式下抵押金硬上限 D = 0，见 4.6），此时整单拒绝。
  8. 试算与成交一致：下单试算按与成交相同的口径计算本笔可下金额、份额、本笔实际赔率、成交后赔率；同一盘口状态下，试算结果与随后的实际成交完全相同。试算不含交易前风控（4.5），成交时仍可能被缩量或拒单。
  9. 上限随盘口变化：LMSR 开启时，每笔成交使盘口变深，单笔上限随之放开；其他投注项的成交改变本项价格时，本项上限随之变化。固定赔率模式下盘口不随成交移动，B 不变（4.6）。
  10. 余额先于上限：投注模拟页先把请求金额截到玩家可用余额，再按单笔上限截断。

4.2 滑点上限与冷门项放宽

4.2.1 规则

  1. 适用滑点上限（按投注项当前价格 p 计算，实现对照 slipAtPrice）：
  2. 单笔滑点上限 = 0 → 不限；
  3. p ≥ 冷门线 → 适用滑点上限 = 单笔滑点上限；
  4. p < 冷门线 → 适用滑点上限 = max(单笔滑点上限, min(冷门项滑点上限封顶, 单笔滑点上限 × 冷门线 / p))。

p 越低（越冷门），放得越宽，最多到封顶。

  1. 买入：滑点上限金额（4.1 的 B）= 使本笔滑点恰好等于适用滑点上限的投注额。本笔平均价随金额单调上升，所以「滑点不超过 x」等价于「投注额不超过某个金额」。若价格推到 1 也达不到该滑点，则不限。
  2. 卖出：平均回收价 ≥ 卖前价格 × (1 − 适用滑点上限)。卖出的适用滑点上限 = max(按卖前价格算的值, 按「请求份额全部卖出后的价格」算的值)，两者取较宽者，保证按上限一笔买满的持仓可以一笔卖回。超过时按可卖份额部分卖出。
  3. 与盘口深度成正比：同样价格下，滑点上限金额与盘口深度成正比，开盘时即与抵押金成正比；抵押金放大 k 倍，单笔上限放大 k 倍。
  4. 滑点上限只约束单笔，不约束总风险。

4.3 平台最低赔率

4.3.1 规则

  1. 价格上限：价格上限 = (1 − W/10000) / 平台最低赔率。默认盘 = 0.97 / 1.05 = 0.923810。
  2. 暂停买入：满足任一条件 → 该投注项暂停买入：
  3. 当前价格 ≥ 价格上限（即未封顶赔率 ≤ 平台最低赔率）；
  4. 把价格推到价格上限所需的投注额 < 0.01 USDT。

暂停判断在下单试算、页面展示、成交三处口径一致（实现对照 isSuspended）。

  1. 未暂停时的上限：单笔上限再与「把价格推到价格上限所需投注额」（4.1 的 C，最低赔率限额）取小（来源记为「最低赔率」），成交后边际赔率恰好等于平台最低赔率。被截到不足 0.01 USDT 时整单拒绝，计入「暂停拒单」。
  2. 卖出不受限：卖出不检查平台最低赔率；卖出使价格回落到价格上限以下后，暂停自动解除。
  3. 开盘即暂停清单：开盘时赔率已不高于平台最低赔率的投注项列入开盘即暂停清单，提示庄家「建议换线」；不阻止开盘，这些项开盘后不能买入。
  4. 固定赔率模式：成交不推动价格，只判断是否暂停（规则 2 第一条），不按规则 3 截金额。
  5. 庄家调价：盘中调价、开盘逐项升降、直接输入赔率都可以把赔率调到平台最低赔率以下，调完该项即暂停买入。
  6. 平台最低赔率与玩家下单时自填的「最低接受赔率」是两回事：前者对全场生效，后者只保护该玩家本笔。

4.4 赔率封顶

4.4.1 规则

  1. 显示赔率：赔率 = min(做市赔率, 赔率封顶)，做市赔率 = (1 − W/10000) / 价格。被封顶的投注项内部价格不变，只是显示与成交赔率不超过封顶。

4.5.1 规则

  1. 占用状态

  2. 判定（买入、卖出相同）：
  3. 交易前风控关闭 → 放行；

4.6 固定赔率模式的抵押金硬上限与卖出上限

4.6.1 规则

  1. 固定赔率成交：买入份额 = 净额 / 价格（再按 4.4 封顶），本笔实际赔率 = 所见赔率，滑点为 0；卖出到手 = 份额 × 价格 × (1 − W/10000)。成交不改变价格。
  2. 买入抵押金硬上限 D（实现对照 collStakeCap）：

`` D = max(0, (抵押金 − L_win) / (赔率 − 1)) L_win = 该投注项获胜的比分里，平台当前亏损的最大值 ``

赔率取封顶后值；赔率 ≤ 1 时 D 不限。含义：成交后，该项获胜的任一比分平台亏损都不超过抵押金。平台当前亏损可以为负（已收现金多于兑付），此时 D 变大。

  1. 买入单笔上限：min(单笔最多收, 滑点上限金额, D)；平台最低赔率只判断暂停（4.3 规则 6）。滑点上限金额仍按 LMSR 曲线在当前盘口计算，盘口不移动，所以不随成交放开。
  2. 卖出上限：

`` 卖出份额 = min(请求份额, 持仓, 固定赔率卖出上限, 抵押金卖出上限) 固定赔率卖出上限 = 当前滑点上限金额（不含单笔最多收）× 当前赔率 抵押金卖出上限 = max(0, (抵押金 − L_lose) / (价格 × (1 − W/10000))) L_lose = 该投注项不获胜的比分里，平台当前亏损的最大值 ``

  • 固定赔率卖出上限（实现对照 fixedSellCap）即按滑点上限一笔买入能得到的份额，保证一笔买满的持仓可以一笔卖回；单笔滑点上限为 0 时不限。
  • 抵押金卖出上限实现对照 collSellCap。
  • 截断后仍走交易前风控（4.5）。

5.1 开盘前逐项升降

5.1.1 规则

  1. 适用条件：比赛还没有任何投注（含冻结名单与现存投注都为空）。一旦有投注，升降按钮不再显示，已保存的升降值锁定。
  2. 操作入口：庄家后台「开盘预览」表中，每个投注项有两组按钮：
  3. 赔率 −/＋：每点一次 ±1%（即升降比例 ±0.01）。
  4. 预期 −/＋：每点一次 ±1 个百分点（即 ±0.01）。
  5. 被调投注项的目标预期：

目标预期 = (模型预期 + 预期升降) / (1 + 赔率升降) 即先按百分点改预期，再按比例改赔率（赔率与预期成反比）。

  1. 同市场配平：同一市场里没有被调的投注项按各自模型预期的原比例缩放，使该市场预期合计为 100%。每个市场至少保留一个未被调的投注项。
  2. 跨玩法同时满足：所有被调市场的目标预期，在比分状态上用迭代比例拟合同时满足；与被调投注项描述同一事件或相关事件的其他玩法投注项随之联动。若两个玩法对同一事件给出不同的目标预期，无法同时满足，本次调整不生效并报错。
  3. 抵押金不变：升降后全场最大亏损仍等于抵押金。
  4. 只改开盘价，不改模型 λ：「期望盈亏（模型）」仍按 λ 计算，庄家可据此看出升降让平台多赚还是多亏。
  5. 点击即校验：每次点击后立即按页面上当前填写的全部设置重算开盘盘口，出现以下任一情况，本次点击不生效，升降值回到点击前，并在提示区显示「未生效：原因」：
  6. 页面上其他设置项本身不合法（如抽水超范围），与保存设置的校验相同；
  7. 被调项目标预期不在 (0, 100%) 之间；
  8. 同市场被调项目标预期合计 ≥ 100%，其余项无法配平；
  9. 同一市场全部投注项都被调；
  10. 跨玩法互相矛盾；
  11. 一致性检查发现会开出可无风险套利的盘（consistencyCheck 中 error 级）；
  12. 按当前溢价开不了盘（仅溢价平均分摊时可能出现）。
  13. 生效时机：点击只改草稿，点「保存设置」后写入比赛设置，玩家端此后按新开盘价显示。
  14. 复原：没有一键复原；要撤回某项升降，只能反向点击把该项升降值点回 0（升降值为 0 的项保存时不写入设置）。

实现对照：dealerProbs（目标与配平）、setupScoreMaker 中迭代比例拟合、投注模拟页开盘预览点击处理。

5.2 关闭 LMSR（固定赔率模式）

5.2.1 规则

  1. 开关含义：「启用 LMSR」关闭（lmsr = false）后：
  2. 成交按当前赔率成交，不推动做市状态，成交后所有投注项赔率不变；
  3. 赔率只能由庄家改变：开盘前逐项升降（5.1）、开盘前直接输入赔率（本节）、盘中调价（5.3）。
  4. 单笔上限与卖出上限（算式见 4.6）：
  5. 买入：算法与启用 LMSR 时相同，取单笔最多收与按当前盘口算出的滑点上限中较小者；平台最低赔率只判断暂停、不截金额（4.3）。因盘口不随成交移动，该上限也不随成交放开。
  6. 买入另加抵押金硬上限：成交后任一比分的平台亏损不超过抵押金。
  7. 卖出上限（份额）= 按滑点上限算出的可买金额 × 当前赔率，不再与单笔最多收取小。
  8. 卖出同样受抵押金上限约束：卖出付现后，其余比分的平台亏损不超过抵押金。卖出按当前价格回收，不推动价格。
  9. 直接输入赔率（只在固定赔率模式、且无投注时可用）：
  10. 每个投注项可填一个赔率；先校验范围，通过后四舍五入到 2 位小数。
  11. 合法范围 1.01～1000（超出时提示「未生效：赔率须在 1.01 ~ 1000」），且不高于赔率封顶（封顶关闭时只受 1000 限制）。
  12. 把输入框清空等同于「清除」该项。
  13. 同一市场其余未输入的投注项按原比例配平；每个市场至少留一项不输入。同一市场只剩一项未输入时，该项完全由配平决定，不显示升降按钮，标注「自动配平」。
  14. 所有市场的输入一起迭代，直到同时满足（一个玩法的输入会带动其他玩法里相关投注项）；无法同时满足时报错并指出投注项。
  15. 输入后逐项升降（5.1）对未输入的投注项仍可用；输入的投注项标注「按输入赔率」。
  16. 可逐项「清除」，恢复按模型计算。
  17. 重新启用 LMSR：勾选启用时，已输入的赔率全部清除，赔率按模型重算，提示「已启用 LMSR：直接输入的赔率已清除……」；启用 LMSR 时设置里即使带有直接输入赔率也不生效。
  18. 跨玩法稳赚检查（安全网）：求「任何比分都至少兑付 1」的最低买入成本 arbCost；最低成本 < 1 即存在稳赚组合（openArb）。
  19. 录入环节：每次输入或清除后检查，会开出稳赚组合时本次输入不生效。
  20. 保存环节：无投注且 openArb 时不能保存，提示「输入的赔率会开出无风险套利：买……每投 X 在任何比分都至少拿回 1」。
  21. 重放环节：已保存的比赛不因该检查报错（保证可重放）。
  22. 锁定：有投注后，LMSR 开关与直接输入赔率都锁定。

实现对照：applyFixedOdds、arbCost、collStakeCap / collSellCap、fixedSellCap、投注模拟页 readCfg / tryFixed。

5.3 盘中调价

5.3.1 规则

  1. 适用条件：比赛已保存、未结算、当前时间 ≤ 封盘时间。不满足时按钮置灰并提示：「请先保存比赛设置」/「本场已结算，不能再调价」/「本场已封盘，不能再调价」。

未开盘的比赛（已保存）同样可以调价。

  1. 操作入口：庄家后台比分热力图（格内为该比分开出时的平台盈亏）。点格子弹出该比分下会赢的投注项（每个市场即每条盘口线恰好一项，默认盘下共 10 项），可：
  2. 逐项调价：对单个投注项点 赔率 −5% / −1% / ＋1% / ＋5%；
  3. 整体调价：对弹窗内全部投注项同时按同一系数调价。
  4. 调价效果：投注项赔率 × 系数（0.95 / 0.99 / 1.01 / 1.05）。做法是给该投注项覆盖的比分状态整体加减做市份额：
  5. 不成交、不改变平台现金与各比分兑付；
  6. 其他玩法里相关投注项随之联动；
  7. 调价后全场最大亏损不再由开盘缩放保证等于抵押金，风险按各比分兑付与现金实时计算。
  8. 目标赔率范围：目标赔率限制在 [1.01, 1000]，且只朝要求方向移动：已在区间外的项不会被反向拉回区间；达不到时停在可达边界。
  9. 已封顶的项：调价按未封顶的做市赔率计算。做市赔率高于赔率封顶时，调价会改变内部价格，但显示与成交赔率仍为封顶值，直到做市赔率回到封顶以下。
  10. 稳赚检查：调价前后各算一次跨玩法最低买入成本，调后成本 < min(1, 调前成本) 时拒绝本次调价，提示稳赚组合。
  11. 暂停提示：调价允许把赔率调到平台最低赔率以下；调后被暂停买入的项，在成功提示末尾列出数量。
  12. 调价记录：每次调价追加一条记录到比赛数据，内容：记录 ID、时间、系数、投注项列表、known（调价时庄家已看到、且此前任何一条调价都还不认识的投注，含冻结名单中的投注）。记录时间取「当前时间、上一条调价时间 + 1 毫秒、已看到的最晚投注时间 + 1 毫秒」三者最大值。
  13. 重放顺序（所有人按同一规则重放，得到同一盘口）：
  14. 投注先按提交时间、再按玩家 ID、再按投注 ID 排序；
  15. 每笔投注排在第一条「认识它」（known 中包含它）的调价之前；所有调价都不认识的投注排在最后一条调价之后；
  16. 不按各自浏览器时钟比较投注与调价的先后；
  17. 没有 known 的早期调价记录按「投注时间 < 调价时间」判断。
  18. 只认格式有效的记录：时间 ≤ 本场截止时间（封盘时间与结算时间取早者）、系数在 [0.5, 2]、投注项 1～30 个。
  19. 撤销：只有最近一条调价可撤销，且须同时满足：比赛未结算、未过封盘时间、它之后没有任何新投注（全部可见投注都已被某条调价认识）。满足时调价记录表中该条显示「撤销」按钮，不满足时不显示按钮；撤销即删除该条记录。之后已有投注的调价不能撤销，要回调须反向调价。
  20. 调价失败：重放新盘口时出错，提示「未调价：原因」，不写入记录。

5.4.3 冻结名单

  1. 写入时机：封盘、结算时若尚无冻结名单则写入；庄家页面打开期间（当前比赛状态变化或有新投注时检查全部比赛），已过封盘时间、未冻结、未结算且开盘时间早于封盘时间的比赛自动冻结一次。
  2. 内容：开盘时间 ≤ 提交时间 ≤ 封盘时间的投注，每笔保留：玩家、投注 ID、提交时间、买/卖、市场、投注项、数量、最低接受赔率、最低回收金额。
  3. 冻结后的重放：只认冻结名单，按名单内的顺序重放（不再按提交时间重排）；之后玩家补交、删改投注都不起作用，补交的投注显示「封盘后提交，不计入」。
  4. 封盘时间变化（保存设置、撤销结算时；未结算且已有冻结名单）：
  5. 新封盘时间在将来 → 清除冻结名单，恢复接收投注，到点重新冻结；
  6. 新封盘时间仍在过去且比原来晚 → 按新时间窗重冻：原名单 ∪ 现存投注，原名单里的投注不因玩家事后删改而丢失；
  7. 新封盘时间不晚于原来 → 冻结名单不变。
  8. 重放时投注须在 [开盘时间, 本场截止时间] 内，截止时间 = 封盘时间与结算时间取早者；不在区间内的显示「不在投注时间内」。

5.4.5 结算兑付

  • 按赛果比分，每个投注项判定输赢；玩家持有的每份获胜份额兑付 1 USDT，失败份额为 0。
  • 玩家本场总计 = 可用筹码 + 兑付；本场盈亏 = 总计 − 期初余额。
  • 结算前持仓按「当前价格 × (1 − W/10000)」估值，页面标注「按当前卖出价估算」。

计算举例（默认盘，期初 1000）：玩家买入主胜 20 USDT 得 37.8372 份，之后卖出 10 份收回 5.0513。可用筹码 = 1000 − 20 + 5.0513 = 985.0513，持仓 27.8372 份。赛果 2:1（主胜）：总计 = 985.0513 + 27.8372 = 1012.8885，本场盈亏 12.8885。赛果 1:1：兑付 0，总计 985.0513。结算前（卖出后盘口）持仓估值 = 27.8372 × 当前价格 × 0.97 = 13.9836，总计估算 999.0349。

5.4.6 异常与边界

  • 结算比分超过比分矩阵球数：提示「比分超过模型范围（14 球）」，不结算。
  • 比分为空或负数：提示「请填写比分」。比分填小数时按整数部分取（如 1.9 按 1）。
  • 已结算的比赛再次点结算：覆盖赛果与结算时间，且「结算前的封盘时间」被改写为第一次结算后的封盘时间，之后撤销结算无法恢复最初的封盘时间（见决策 Q34）。
  • 自动冻结只在庄家页面打开时执行；庄家未打开页面时，封盘后的投注在重放中按时间窗过滤，但尚未写入冻结名单。
  • 重新开盘（开盘按钮）会清除冻结名单；原冻结名单中的投注若仍在现存投注里，照常重放。
  • 撤销结算后再结算，以最后一次结算的比分为准。

5.5 期次与余额

5.5.1 规则

  1. 新建比赛默认沿用：新建时自动找最近一场已结算比赛（按结算时间最晚），把它的期末余额与累计盈亏快照写入新比赛：
  2. 期初余额快照（startBal）：来源比赛中每位玩家的总计（可用筹码 + 按赛果兑付），保留两位小数；来源比赛里没有投注、但由更早一场沿用过来的玩家，余额原样带过来。
  3. 累计盈亏快照（startCum）：来源比赛的沿用累计 + 来源比赛本场盈亏，保留两位小数。
  4. 没有已结算比赛时不沿用，每人按初始筹码。
  5. 快照不随来源变动：快照在建赛（或改选来源）时生成，之后来源比赛的变化不影响本场。来源比赛被删除后，选项显示「来源已删除，按快照」。
  6. 改为不沿用或改选来源：仅无投注时可改；选择「每人按初始筹码」则清除快照；改选的来源必须已结算，否则提示「沿用余额的来源比赛须已结算」。
  7. 新玩家：不在快照里的玩家，期初余额 = 每人初始筹码，累计从 0 起。
  8. 累计总盈亏 = 沿用来的累计 + 本场盈亏。
  9. 排行榜：本场有投注的玩家与沿用快照里的玩家，按累计总盈亏从高到低排序。
  10. 玩家「历史比赛」：列出本人有投注的其他比赛，每场显示投入、（已结算）兑付 + 卖出 /（未结算）卖出收回、本场盈亏；明细中已结算场次的每笔买入标注「输」/「赢，兑付 X」/「赢（已全部卖出）」，兑付按同一投注项的卖出先进先出冲减前面的买单后计算。

实现对照：newPeriodMatch、carrySnapshot、cumSnapshot、cumOf、remainAfterSells。

  • 买入 2：主胜 20 USDT，得 36.3230 份（价格已被买入 1 推高）。
  • 卖出：主胜 50 份，收回 25.7127。
  • 先进先出：买入 1 剩 0 份；买入 2 剩 36.3230 − (50 − 37.8372) = 24.1602 份。

  • 累计总盈亏 = −30 + 9.8728 = −20.1272。下一场新建时，该玩家期初余额快照 1009.87，累计快照 −20.13。

5.5.4 异常与边界

  • 玩家在快照中但本场未投注：排行榜仍显示，本场盈亏 0。

5.7 权限

5.7.1 角色定义

  • 庄家：比赛页面的拥有者。
  • 玩家：已登录、有写入权限（组织成员中的参与者权限，或以编辑者身份受邀）的用户。
  • 外部访客：无登录身份，或只有查看权限的用户。

5.7.2 共享数据规则

  • 比赛设置（含开盘/封盘时间、定价参数、冻结名单、赛果、盘中调价记录）与「当前比赛」指针：只有庄家能写。
  • 投注记录：每人只能写自己名下的投注记录（以记录路径为准，不信记录内容中的玩家字段）；庄家作为用户同样只能写自己的投注记录。
  • 所有人可读比赛设置与全部投注记录（用于各自重放出同一盘口）。

5.7.4 异常与边界

  • 非拥有者写比赛设置被拒：提示「保存失败：只有比赛的拥有者能改设置」；调价被拒：「调价失败：只有比赛的拥有者能调价」。
  • 无写权限的用户投注被拒后，本次会话降级为只读，提示「你的权限不能投注（需要组织成员的参与者权限，或以编辑者身份受邀）」。

  • 无法访问数据库（未登录 claude.ai 或无访问权限）：提示「这个页面需要登录 claude.ai 并有访问权限才能参与模拟。」，不显示盘口数据。
